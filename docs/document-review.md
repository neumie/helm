# Document review

Helm’s native review window is a surface of an **already-running Claude Code, Codex, or Pi conversation**. The agent opens the document, receives your selections and instructions in that same conversation, and edits with its existing context, tools, and permissions. Helm never launches, resumes, or replaces an agent for review, types into terminals, or reads/writes provider session files.

The repository Markdown, JSX or TSX file is the source of truth. Helm renders and watches its body without converting it into Run Context. Explicit comments and review history append a portable trailing journal in that same file; the source body is never rewritten by Helm.

## Agent-driven CLI

Start the updated Helm desktop normally. Inside your existing agent conversation, ask it to use the following workflow:

```sh
helm review open docs/plans/example/spec.md --agent claude --wait --json
# Use --agent codex or --agent pi for those running callers.
```

This enrolls the caller, opens the native window, and **keeps this tool call waiting**. Select a passage, type immediately, then explicitly send; Ask is the default and Request change is available in the companion intent menu. Whole-document messages use the same editor. The tool returns JSON containing a private `connection` file handle and `feedback` with the original typed request, bounded prompt, and relative file path. The agent reads `feedback.prompt` in its original context, handles it there, and reports back:

```sh
helm review reply REQUEST_UUID --connection CONNECTION_FILE --text "My answer / what changed"
helm review wait --connection CONNECTION_FILE --timeout 600 --json
```

Continue the wait → handle → reply loop for ongoing review. A foreground tool call must actually consume the result: a detached shell listener is not live agent injection. The agent may need its shell tool’s timeout increased for a long wait. Timeout returns `feedback: null` without fabricating delivery. A waiting CLI process is transport, not a second agent or a daemon.

The complete command surface is:

| Command | Effect |
| --- | --- |
| `connect --agent NAME [--workspace DIR] [--label TEXT]` | Enroll the original caller, without opening a document or sending a prompt. |
| `open FILE [--connection FILE] [--wait]` | Open Markdown, JSX or TSX for this connection. Without a handle, requires `--agent`. |
| `wait` / `next --connection FILE [--timeout SECONDS]` | Return one selection/comment/message to the same waiting tool call; repeat deliberately. |
| `reply UUID --connection FILE` | Report `--text`, bounded `--text-file FILE`, or `--stdin`; exactly one source. |
| `status [--connection FILE]` | Show desktop availability or connection metadata. |
| `list --connection FILE` | Show repository-scoped connection metadata; transcript omission is explicit. |
| `receipt UUID --connection FILE` | Inspect delivery without replaying it. Foreign receipts are unavailable. |
| `disconnect --connection FILE` | Retire the connection and remove its private handle; never stop the original agent. |
| `help` / `--help` | Agent-readable usage and limitations. |

All operation output is JSON; `--json` is accepted explicitly. For streamed reports, use `--state working --sequence 0`, then increase `--sequence` for every replacement snapshot, including `--state complete` or `error`. A single final reply defaults to sequence 0. An exact completed-report retry is idempotent; changing its contents under the same sequence is refused. Lost/ambiguous feedback is never fetched again or resent automatically.

The connection handle is an owner-private credential **file**, outside the repository. Do not copy its contents, commit it, or log its token. Preserve the handle printed on stderr if opening fails so you can explicitly disconnect. Connections require a canonical Git workspace and the currently active Helm profile. A file already bound to another caller cannot silently switch: choose the new connected agent explicitly in its window, or close the old window before opening it again.

## Native live Pi connector

For ordinary Pi 0.99.1 terminal sessions, the opt-in local package `packages/helm-document-review/` registers the `helm_review` tool and `/helm-review` command. Installing is a separate operator step; this feature does **not** change the user’s Pi settings:

```sh
pi install /absolute/path/to/helm/packages/helm-document-review
# In the existing Pi session, use /reload, then:
/helm-review docs/plans/example/spec.md
```

The agent can instead call `helm_review` with `{ "action": "open", "file": "docs/plans/example/spec.md" }`. It opens the document and retains one private listener. Selection feedback is dispatched through the existing runtime’s `sendUserMessage(..., { deliverAs: 'followUp' })`, with prompt-template expansion disabled. It keeps the original session, tools, permissions, and context; no replacement writer or copied transcript is created. Observed assistant text is projected only after the **exact review prompt** starts, and ends at observed settlement. Unrelated original turns and tool arguments/results are not mirrored.

Use `/helm-review disconnect`, or the tool’s `disconnect` action, to close only the surface. Non-TUI Pi callers use the universal CLI wait path. The factory performs no IO or automatic enrollment. Before switch/fork/tree navigation, admission fences synchronously; cancelled/failed navigation cannot be cleared by idle state, unchanged UUID, timers, or manual reconnect. Only a genuine settled lifecycle event permits a fresh connection. As with Pi Remote, Pi’s public dispatch API does not provide generation-bound atomic admission at later input hooks: closing the connection cannot retract a follow-up already handed to Pi. Dispatch is not acceptance or completion.

## Native UI and document behavior

You can also open **File → Open Markdown file…** (also accepts JSX/TSX) or **Plan documents → Review document**. These actions open only the reading surface. Choose a connected agent; there is no New conversation or provider-spawning control.

- Read first: the titlebar shows the actual filename. Compact **Contents** and document-options dots sit beside the filename; no redundant wide reading toolbar. The dots menu contains Read, Source, Changes, Comments, Document details (full path and revision), and scoped light/dark preference. Nondefault views retain Back to reading; narrow windows retain Document/Conversation. Contents uses a 240px hierarchical rail only when the measured document pane leaves a 480px prose floor plus gutters, otherwise a normal-flow section above reading (at most 240px or 40% of pane height), never covering document text. Long labels show at most two lines with full accessible names/title; current section is quietly marked. Close/Escape restore owned opener focus, clicking outside Contents keeps it open and does not steal newer focus; empty documents get a plain no-headings state. Section navigation targets exact block IDs and fences deferred scroll/focus to source, API, owner and lifecycle.
- The companion shows just the conversation name and observed provider/status. A chooser appears only when multiple conversations exist, an available caller is unbound, or an owner change requires explicit reselection. There are no nested details/help blocks or repeated empty-chat instructions. Permission limits remain under **More → Document details**; internal IDs and CLI instructions are not shown. Ready means the selected caller is listening and not busy, not that a request has completed. **Feedback paused** means its connection still exists but no listener is available; Send remains disabled. A wait timeout or completed reply is not a disconnection.
- Scrollbars stay visible and usable, with the same slim rounded thumb and transparent track as Helm's other reading surfaces; keyboard and pointer scrolling are unchanged.
- Complete a trusted pointer selection and type immediately in the existing companion editor. Routine re-selection updates the passage even with existing text, preserving your words and chosen intent without Use selection. Keyboard selections stay extendable/copyable until Alt+Enter explicitly accepts them; no per-block Review controls interrupt prose. Rendered selection uses its complete containing source block; Source view permits exact Markdown ranges. Saved comment associations and re-anchor remain protected by explicit acceptance. Pending/control/unknown work and local-save flight block scope changes synchronously; a blocked selection never auto-applies after settlement. Selection alone never sends, saves a comment, acknowledges or disconnects.
- After you send a passage question, a comment icon beside its actual selected text line opens a small read-only bubble with that passage’s questions and replies. Opening highlights the passage in the document instead of repeating its quote in the bubble; this separate display highlight does not change the current selection, scope or draft. Different passages in a list anchor to their own lines, not the first list item. Close/dismissal clears only the comment highlight. Missing or ambiguous rendered matches within the already validated current block stay in the companion rather than guessing a marker position. The main conversation remains unchanged; the bubble has no second editor. Escape/Close returns to the icon, and clicking elsewhere dismisses without stealing focus. Copying bubble text never selects a new passage. Saved source associations are portable display-only history; live streaming remains memory-only. Changes to the document revision hide the icons instead of guessing a new anchor. Older questions without a captured association remain in the companion only. Normal delivery notices such as Dispatched are not shown; failures and unconfirmed outcomes remain visible.
- Selected text stays visually highlighted as the actual captured DOM range, including after Use selection, editor typing, observation, return or resize. Raw DOM text is validated against its own captured snapshot, separately from the selected quote's rendered line breaks. This display range does not invent Markdown offsets: rendered requests still use the validated containing source block and exact selected quote. Revision, caller/owner/API change, explicit clear or DOM replacement removes range paint without highlighting a replacement paragraph or searching repeated text. Saved annotations retain their truthful source-block indication.
- Ask asks the original agent not to edit. It does not impose a new tool allowlist or sandbox. Request change permits the original session’s ordinary tools. Wire intents remain `discuss`/`change`. Permissions and questions remain in that agent’s original terminal; they are not answered in the review window.
- Whole-document and passage feedback share one stable companion editor. The document highlight supplies passage context: no Selected passage heading, duplicate quote card, Show full quote or replacement label. The exact selected quote remains attached internally to sends and saved comments. Stale guidance stays visible beside writing. Both scopes use the same 128px writing minimum and visibly defined 64px editor floor, including while either menu is open; guidance keeps its 32px floor and chat its 96px floor. One checked Ask / Request change menu, Writing options and Send form the quiet action row. Writing options opens 8px above its dots trigger and may overlap the editor while open; the intent menu stays above the well. Both stay within the viewport. A nonempty draft with disabled Send gets one nearby reason; an empty draft stays quiet.
- Selection/opening focus is fenced to current document/revision and caller/owner. Mount, polling, refresh and resize never move focus; newer control focus wins. Cmd/Ctrl+Enter submits once. Writing options → Return to document, or Escape, restores reading without clearing scope, text, intent or comment identity; from Comments it returns to rendered Markdown, while Source remains Source. Returning to Conversation resumes that same passage draft. Only explicit Writing options → Clear passage switches to whole-document scope, retaining text/intent and refusing admitted work. Resizing/destination changes preserve scope/draft without focus calls.
- Writing options → Save local comment saves without delivery and stays in the editor; repeat Save comment changes updates the same comment. Saved locally · not sent appears only after persistence succeeds, including a successful Retry save, never during failure or for a newer draft/owner/API. Pending saves are single-flight; failures remain retryable. Edit on a saved stale comment retains original quote, intent and comment identity; Send and local save remain disabled until explicit re-anchor. A refused opening leaves current draft/scope intact. Resolve/Delete/Re-anchor are explicit; revisions never silently relocate comments.
- File edits preserve unsent drafts, fence stale selections, and expose Changes against the last observed revision—not full edit history. Helm never rewrites the source body; it only appends the review journal.
- Resize the conversation companion with pointer or arrow keys. Narrow windows push Document/Conversation destinations. The scoped Light/Dark reading preference does not change Helm’s app-wide appearance.
- The filename header has no redundant Close button. Native window controls and Cmd/Ctrl+W close the review window, never a terminal; existing close/persistence callbacks remain intact. Failed draft saves offer Retry save or local Discard unsaved changes. Closing a window does not kill the caller; quitting/profile switching disconnects review authority while original agents remain running.

**No listener → not sent.** Unsent feedback stays local. Pending/Dispatched/Unknown receipts are not claims of provider acceptance or an applied file edit. The CLI confirms that it returned feedback to the caller; native Pi confirms only synchronous dispatch. Working derives from explicit caller reports/observations, never inferred terminal output or a send click.

For unknown delivery, inspect the original conversation and file first. Local text recovery and explicit outcome acknowledgement never replay. Disconnect/restart invalidates authority; reconnect explicitly from the original agent. Legacy review-managed identities are preserved but are **never** loaded, spawned, or resumed by the new mailbox. Connections are memory-only and cannot survive desktop restart as runnable targets.

## Bounds and authority

- Document: 512KiB UTF-8, canonical approved root/parents, no-follow regular single-link descriptor, identity/stat and byte checks. Preserve BOM and original CR/LF offsets.
- Instruction/passage: 8,000 UTF-16 units; generated prompt: 24,000. Never automatically copy a whole large spec into feedback.
- Eight native windows, eight globally admitted UI sends, 16 window operations; 32 mailbox owners per profile. Retired owners can be reclaimed, never automatically replayed.
- 256 dedup receipts per profile/process; exhaustion refuses new admission. Check outcomes before deliberately reopening Helm.
- Replies: 64,000 UTF-16 units; UI projection: 80 messages / 160,000 serialized message bytes, including passage associations and JSON escaping, with explicit omissions. The complete original conversation remains agent-owned.
- Private wire: strict one-frame JSON/UDS, 512KiB actual-byte bound, two operations per connection, eight pending connects and 64 sockets/descriptors. Reads are capped, owner-private, no-follow, single-link and TOCTOU-checked. Exclusive lock creation prevents competing hosts replacing a winner’s authority. Cleanup checks exact published inode identity and never kills unrelated processes.
- Response completion deadline: 15 minutes; a missing reply becomes unknown, not an automatic resend. CLI wait accepts 1–3600 seconds via bounded minute-long reads.
- Drafts: 256 entries / 1MiB private profile state, 256 annotations per draft. Drafts/preferences grant no command or file authority.
- Markdown: 10,000 blocks with bounded token/depth/table work. Inert HTML, safe credential-free absolute HTTP(S) links, no automatic image fetching; mapping failures expose complete literal Source rather than chat-sized truncation.

The sandboxed preload exposes no general filesystem, PTY, daemon or configuration interface. Main rechecks top frame, current window, profile token, document/revision and complete caller owner before/after awaits, including failures. Private control is desktop-owned, not the API-only daemon or Remote host. Browser display fixtures cannot enroll production callers.

## Interactive documents and portable review history

JSX/TSX default-exports a React component and may import React and its hooks only. No repository/package imports, dynamic module loading, Node or native APIs are exposed. The dedicated browser Worker runs real React 19.2.7 with the official reconciler; main and the privileged renderer never evaluate document code. Only bounded allowlisted inert HTML/props/styles reach the reading surface. Network, storage, nested Workers, direct messaging and string-timer evaluation are disabled. The strict native CSP adds only `worker-src blob:`. Initial/event stalls terminate after two seconds; this is not an OS heap quota.

Unique literal JSX IDs describe up to 64 compiler source blocks; producer-visible IDs alone never attest rendered origin. Rendered passages reference the complete compiler-observed block, not invented exact text offsets. Standard public text/number/checkbox/radio/email/textarea/single-select values require current literal IDs and a settled current Worker frame before feedback admission. Values are bounded to 16 fields, 4,000 UTF-16 units each and 16,384 total. Missing/dynamic IDs and multiple selects remain locally interactive with **Local only · values not included in feedback**. Password/file controls are unsupported. Local events never send feedback; source/API replacement terminates the old Worker. Metadata-only journal changes do not restart it.

Markdown journals use trailing `<!-- helm-review:v1 BASE64URL -->` lines; JSX/TSX use `/* helm-review:v1 BASE64URL */`. Each starts with one archive-owned LF and has no final newline. Records contain only display history/comments, never native document/session/owner IDs, paths, credentials or replay authority. Body BOM/line endings/bytes remain exact. Source revision hashes only the body; archive revision hashes the complete file. Only a strict contiguous trailing suffix is metadata; malformed/ambiguous tails refuse reading/writing without repair. Limits are 256KiB per decoded record, 384KiB encoded journal, 512KiB full file, 1,024 records, 64 threads and 256 annotations.

An unconfirmed question is appended before original-caller admission; exact final replies/outcomes append settlements. Saved history is readable without a caller and never replays or enrolls one. Changed passages remain stale, never relocated. Original agents must preserve the trailing journal exactly when editing. Appends use serialized owner-attested no-follow single-link descriptors, O_APPEND, bounded rereads, revision checks and fsync. No compaction, truncation or source replacement occurs. These checks do not promise atomicity against an uncooperative same-user external writer between final check and append.

Explicit annotation changes carry their captured archive revision; instruction/layout/theme autosaves omit it and cannot migrate legacy private notes. Failed comment saves retain the original payload/fence for **Retry comment save** or deliberate discard/reload, never silently rebase. **Retry review save** retries only captured final settlements, never feedback or annotations. At most eight main-owned final-save contexts survive clean window close; failed saves block quit/profile change until retry or explicit **Discard unsaved reply** (default Keep). Discard drops only the exact retained failed save, changes no file or original conversation, and keeps unrelated drafts. Missing/malformed files offer a source-unavailable recovery shell; restoring the original valid file/start permits explicit retry, never automatic recreation. Dirty editor preflight precedes caller retirement during quit/profile switching. Unconfirmed original-agent work alone does not trap a clean window close.

`app/scripts/build-document-canvas.mjs` generates the ignored Worker source before app TypeScript/build and Storybook scripts. Do not stage generated TS or install through proof dependency symlinks. The canvas Node suites and `document-review-canvas.spec.ts` use assembled production modules/Workers plus explicit display services: they are not installed Electron, physical-device, original-provider or OS isolation certification. Original selection/passage regression and history/performance gates remain separate.

For isolated dependency-symlink workbenches, start the owned loopback preview with fresh external absolute `HELM_STORYBOOK_CACHE_DIR` (Vite) and `CACHE_DIR` (Storybook10.5 manager/dev-server/external-globals) directories. Relative Helm cache paths are refused. This avoids cache writes through shared node_modules; it is not a dependency install or service deployment.

## Canvas source-origin and legacy-note boundaries

Compilation stamps eligible intrinsic JSX calls through a runtime-private frozen `__helmCanvasRuntime` helper, supplied only as the fourth argument of an arrow factory. The helper captures real React creation before producer invocation; it is not exposed on React, modules or globals. Source AST identifiers beginning `__helm` are reserved, including escaped spellings. Every JSX compilation directive recognized by the selected TypeScript parser (`@jsx`, `@jsxFrag`, `@jsxRuntime`, `@jsxImportSource`) is unsupported and returns an explicit error/null code before execution. This includes ordinary custom factories and helper `.bind` directives; benign strings/prose/code examples are not banned by substring.

The binding attests the exact compiler-created **frozen props object plus original intrinsic tag**, not the outer React-element wrapper or fiber identity. A wrapper reusing that exact props object and original tag may retain only the existing binding; new/copied/changed/clone/manual props, wrong tags and unproven forwarding cannot mint provenance. Simultaneous duplicate visible IDs, including exact reuse, remove all colliding source stamps and public fields. Dynamic ID reuse of an unused literal stays locally interactive without a source anchor or feedback field. Runtime-only display `sourceId` must match the current unique compiler block and public ID before the renderer exposes markers/fields; public IDs are not fallback authority.

React class `_reactInternals` can expose Item/fiber/container objects. Those objects are **not opaque or trusted**. Immutable authority snapshots live only in runtime-private WeakMaps keyed by exact host Item identity and its admitted props/tag/source binding. Every publication revalidates current props/tag and the private compiler binding. Producer-assigned stamps, fake or prototype-inherited host records grant nothing. Retained globals and safe function-only receiver-safe timers are sealed before producer execution, with captured private validation/freeze operations; inability to secure a required binding stops execution. No constructor/eval/network/messaging/string-timer path is restored.

Output traversal uses bounded indexed reads into fresh runtime-owned plain node/children/field/local-value arrays and objects, never source array `map`, iterator, species or `toJSON`. All producer getter reads/coercions finish before final revalidation of **every** captured host snapshot; only then are provenance/fields derived and the detached primitive DTO synchronously serialized/emitted, with no further producer callbacks. This protects earlier nodes from later getter mutation while retaining existing byte/node/depth/value/duplicate budgets. It is not browser-engine security certification or an OS heap quota.

Native passage validation still checks current compiler ID/bounds and exact source slices; it does not authenticate the rendered origin by itself. A hypothetical forged-ID/bounds request can still satisfy that unchanged guard. The corrected production runtime/renderer prevents that request from being produced through ordinary selection/Send. Integration evidence must therefore use the actual compiler, generated Worker, production renderer and real native guard, not only hand-authored display factories; explicit Storybook factories remain display fixtures.

On refresh, native-projected `draft.annotations` owns journal-present versus journal-free legacy retention. An empty parser archive is not migration: repeated no-journal observation and private instruction/layout/theme autosaves retain exact legacy IDs/quotes/intents/resolved state, omit `archiveRevision`, and do not dispatch or append a journal. Pending/failed explicit annotation writes and private-save flights protect local state and the original discard/CAS baseline. Full source/API/lifecycle/request fences reject late refreshes; clean native journal projections may update notes. Only explicit annotation mutations migrate saved private notes.

## Verification admission and composed reply evidence

Production browser fixtures require a trustworthy loopback document origin and native secure-context `crypto.randomUUID`. An `about:blank` fixture may lack that function: explicit comment allocation then throws before adding its annotation, while a preference timer can later submit an empty draft with the already captured CAS. Assert the native environment and unexpected pageerrors; do not add a polyfill, weaken admission, or classify this as a supported-origin persistence defect.

A saving notice does not attest API/native effect admission. Explicit-save proofs hold only the exact original one-annotation/CAS payload (quote, source/revision, note, intent and UUID) and require one admitted effect before owner/API replacement. Preference autosaves are delegated unchanged. Separate queued-refusal proofs hold an actual zero-annotation/no-CAS preference flight, activate Save twice, replace owner/API and release that preference: the queued stale explicit mutation must remain undispatched, with its earlier-scope refusal and unsent state retained. These cases preserve the same authority/CAS/lifecycle checks rather than rebasing or replaying work.

The isolated native/browser composition uses the existing mock Electron window/webContents/current top-frame effects only. Original registered IPC handlers return native snapshots; the real reader/compiler, request guard, original in-process caller mailbox, descriptor-pinned append/fsync and archive parser own the data. A production pointer note is saved to the actual private temporary file. The question is parsed from disk before original mailbox dispatch, genuine working/complete reports link/deduplicate the live reply, and native final drain yields one exact persisted completed thread. After retiring that disposable caller and clean-closing its page/window, a fresh native reader/compiler/Worker with no connected caller shows the saved reply/quote/anchor/history without Send, replay or re-enrollment. Source body bytes/revision stay unchanged; decoded journals omit native identities, paths, receipts and capabilities.

Keep local annotation/paint/bubble, live reply, native file completion and fresh saved reread as separate evidence stages. Hand-authored display stories or a load projection that always sets `archive.threads: []` cannot establish the reply round-trip. This proof is mocked-native-core/private-temp-file/browser composition, not installed Electron/provider delivery, same-user write-race resistance, power-loss/OS fault injection or an OS Worker heap quota. Native source-ID/bounds validation remains distinct from rendered-origin authentication.

Finish source commits and root/app/strict Storybook builds before development browser gates. Run CPU builds/tests/external bundles through `sysbudget`, but manage the explicitly loopback-bound preview as a direct owned background service without a CPU lease. Use fresh absolute external Vite/Storybook caches, unique output/report paths and an owned lifetime exceeding the serial gate; freeze source throughout.
